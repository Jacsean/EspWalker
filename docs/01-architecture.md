# 01 · 总体架构

> 项目：**Esp32Walker** —— 办公桌桌面机器人
> 定位：ESP32-S3 作为「边缘采集与执行」节点；语音识别、对话、图像理解等 AI 处理下沉到手机 / PC / 云端。

## 1. 设计目标

| 需求 | 落地方式 |
|---|---|
| 两轮 / 履带 / 多轮不同运动底座 | 统一底盘接口 + 三种可更换运动底座，软件层以运动学抽象屏蔽差异 |
| 障碍物感知 | 前向多路 TOF / 超声波 + 可选碰撞开关，触发自动避障减速/停车 |
| 摄像头拍照 | OV2640 DVP 摄像头，ESP32-S3 采集 JPEG 后经 Wi-Fi 上传 |
| 语音输入 | INMP441 I2S 数字麦克风采集，本地 ESP-SR 唤醒词，音频流上传 ASR |
| 对话聊天 | 手机 / PC / 云端执行 ASR → LLM → TTS，音频回传 ESP32 播放（混合：离线降级） |

## 2. 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  云 端  (可选，需联网)                                       │
│  • 大模型 API (OpenAI / 通义 / 讯飞 / Kimi …)                │
│  • 云端 ASR / TTS                                            │
└──────────────▲──────────────────────────────┬───────────────┘
               │ HTTPS/WebSocket              │ HTTPS
┌──────────────┴──────────────────────────────▼───────────────┐
│  中 心 端  (手机 App / PC 上位机  host/)                      │
│  • TCP/WebSocket 服务端：与 ESP32 通信                        │
│  • ASR 语音识别、TTS 语音合成（本地引擎或云端 API）            │
│  • LLM 对话编排、图像理解/预览                                │
│  • 指令下发（运动 / 拍照 / 状态查询）                          │
└──────────────▲──────────────────────────────┬───────────────┘
               │ Wi-Fi (TCP + JSON)           │ Wi-Fi
┌──────────────┴──────────────────────────────▼───────────────┐
│  边 缘 端  (ESP32-S3 主控板  firmware/)                       │
│  • 运动底盘驱动 (两轮差速 / 履带 / 麦克纳姆)                   │
│  • 障碍感知 (TOF / 超声波 / 碰撞)                             │
│  • 摄像头采集 (OV2640 JPEG)                                  │
│  • 语音采集 (I2S 麦克风) + 本地唤醒词 (ESP-SR)                │
│  • 音频播放 (I2S 扬声器)                                     │
│  • Wi-Fi 客户端：上行传感器数据 / 下行指令                    │
└─────────────────────────────────────────────────────────────┘
```

**核心原则**：ESP32-S3 只做「感知 + 执行」，不做重 AI。这样单块 S3 即可完成全部边缘职责；若未来感知负载变重，可平滑扩展为多板（见 §5）。

## 3. 数据流

### 3.1 语音对话链路（上行）
```
麦克风(INMP441) ─I2S→ 采集缓冲 ─→ [唤醒词检测 ESP-SR]
                                   │ 命中唤醒词
                                   ▼
                          音频流(PCM) ─Wi-Fi→ 中心端 ASR → 文本
                                                      │
                                                      ▼
                                                 LLM 对话 → 回复文本
                                                      │
                                                      ▼
                                                  TTS 合成音频
                                                      │
中心端 ─Wi-Fi→ ESP32 ─I2S→ 扬声器(MAX98357A) 播放   (下行)
```

### 3.2 图像链路
```
摄像头(OV2640) ─DVP→ 帧缓冲(PSRAM) ─JPEG编码→ ─Wi-Fi→ 中心端预览 / 图像理解
触发方式：按钮 / 中心端指令 / 定时
```

### 3.3 运动与避障链路（本地闭环，无需联网）
```
障碍感知(TOF/超声) ──► 主控避障状态机 ──► 底盘驱动(PWM) ──► 电机
中心端指令(vx, vy, ω) ───────────────────────────────▲
```

> 避障是**本地实时闭环**（毫秒级），不经中心端，保证网络抖动/断连时仍能刹车。

## 4. 模块职责边界

| 模块 | 所在端 | 职责 | 实现载体 |
|---|---|---|---|
| 底盘运动学 | 边缘 | `(vx, vy, ω) → 各轮转速` | `components/chassis` |
| 电机 PWM 驱动 | 边缘 | H 桥方向 + 速度 PWM | `components/motor` |
| 障碍感知 | 边缘 | 多路距离采样 + 阈值判定 | `components/proximity` |
| 摄像头采集 | 边缘 | DVP 抓帧 + JPEG 编码 | `components/camera`（可选） |
| 音频采集/播放 | 边缘 | I2S 录音 / 放音 | `components/audio` |
| 唤醒词 | 边缘 | ESP-SR WakeNet | `components/audio`（可选） |
| 协议编解码 | 边缘 | JSON 帧收发、重连 | `components/comm` |
| 中心端协议 | 中心 | 连接管理、JSON 解析 | `host/protocol.py` |
| ASR / TTS | 中心/云 | 语音↔文本 | `host/asr.py` / `host/tts.py` |
| LLM 对话 | 中心/云 | 多轮对话编排 | `host/llm.py` |

## 5. 单板 vs 多板

**默认：单板 S3 即可完成全部边缘职责**（双核 240 MHz + PSRAM，摄像头 + 语音 + 运动是 S3 的经典负载组合）。

当出现以下情况时，扩展为多板（主控板 + 感知板 / 底盘板）：
- 感知点密集（>6 路 TOF / 需要多面超声阵列）；
- 摄像头帧率要求高、需要独立 DMA/内存；
- 底盘电机数多且带高分辨率编码器，需要专用定时器资源。

多板扩展方式（二选一）：
1. **UART 总线**：从板将距离/编码器数据以定长帧上报主控；
2. **ESP-NOW**：低延迟无线，从板独立供电，免布线。

本仓库先交付**单板完整方案**，多板扩展在 `docs/02-hardware.md §10` 说明。
